# 数据预处理分析包（dpp）

把数据预处理实验的分析逻辑拆成可复用的 Python 包，配一条有日志、有产物的流水线——目的是**让每一个结论都能被复现和回查**，而不是在 Notebook 里一把梭。

## 为什么不是一个 Notebook

原始做法是 Jupyter 里从上到下跑一遍，导出图放进报告。问题是：

1. 报告里的数字和图**没有绑定关系**——改了代码，报告不会自己变
2. 清洗做了哪些动作，事后**说不清**
3. 训练集和测试集用的变换参数**可能不一致**

所以拆成包 + 流水线：一次运行产出结果表、统计 JSON、图表和逐条清洗日志。

## 模块划分

| 模块 | 负责什么 | 关键点 |
|---|---|---|
| `dpp/cleaning.py` | 录入校验、字段编辑、缺失值分析、异常值检测 | 全部是纯函数，不做隐式落盘 |
| `dpp/transform.py` | 无量纲化、非线性变换、离散化、编码 | `FeatureBuilder` 让训练/测试共用同一套变换参数 |
| `dpp/descriptive.py` | 集中趋势、离散程度、分布形态、分组汇总、区间估计 | 输出可直接进报告 |
| `dpp/similarity.py` | Gower 距离 + 欧氏/曼哈顿/余弦/Jaccard 对比，MDS/PCA 投影，层次聚类 | 混合类型数据用 Gower，不是硬编码成数值 |
| `dpp/correlation.py` | Pearson / Spearman / Kendall 三口径，BH 校正 | 三种口径对线性/单调/秩次敏感度不同，不能只报一个 |

## 跑法

```bash
pip install -r requirements.txt
python scripts/run_pipeline.py
```

产出：

```
results/*.csv, results/*.json   报告里的全部数值证据
reports/figures/*.png           报告里的全部插图（300 dpi）
data/processed/*.csv            清洗与转换后的数据集
logs/cleaning_log.csv           逐条数据溯源日志
logs/run.log                    完整运行日志
```

## 设计上值得说的一点：逐条溯源

`logs/cleaning_log.csv` 记录每一条原始记录的每一步变换。目的是回答一个问题——**报告里某个统计量，到底是清洗前还是清洗后的？**

没有这张日志，同一份数据在不同时间跑出不同结果，就说不清是谁的错。有了它，任意一条记录都能倒推回原始值。

## 数据

`data/raw/` 是 Titanic 数据集（891 行训练集 + 418 行测试集）。规模小是刻意的：这个项目的目的是**把方法跑通**，不是刷指标。换成更大的真实业务数据时，模块边界不用改。

## 已知限制

- 数据集规模小（891 行），异常值检测的统计功效有限，结论不宜外推
- 未做交叉验证与建模，只覆盖预处理到统计描述这一段
- 图表风格固定，若要出多风格报告需要扩展 `descriptive.py` 的绘图函数
